# Play Integrity API Integration

## Overview

The Google Play Integrity API protects Graviton against fraud, cheating, and unauthorized access by verifying that app interactions come from legitimate, unmodified builds running on genuine Android devices.

Play Integrity API verifies:
- **Legitimate installs** from Google Play
- **Genuine Android devices** (not emulators or rooted devices)
- **Unmodified app binaries** (not tampered or repackaged)

## ⚠️ Security Requirements

**Backend token verification is MANDATORY for production use.**

Current implementation:
- ✅ Generates integrity tokens on client
- ✅ Implements phased enforcement rollout
- ❌ Does NOT verify tokens with Google's backend API
- ⚠️ Requires `verifyTokenCallback` implementation for security

Without backend verification, tokens could be generated by compromised devices, tampered apps, or replayed by attackers.

## Phased Rollout Strategy

The integration implements a phased enforcement strategy controlled via Firebase Remote Config for gradual security rollout.

### Enforcement Levels

#### Phase 1: Log Only
```json
{
  "integrity_enforcement_level": "log_only"
}
```

**Behavior:**
- Integrity checks run for all operations
- All results logged to Firebase Analytics
- Operations proceed regardless of verification result
- No user impact

**Purpose:** Establish baseline metrics, identify false positives, monitor API reliability

**Duration:** 2-4 weeks

**Success Criteria:** False positive rate < 1%, API availability > 99%

#### Phase 2: Warn User
```json
{
  "integrity_enforcement_level": "warn_user"
}
```

**Behavior:**
- Failed integrity checks trigger warning dialogs
- Operations still proceed after warning
- Users informed about potential security issues

**Purpose:** Educate users, test warning UI/UX, gather feedback

**Duration:** 1-2 weeks

**Success Criteria:** Warning rate stabilizes, support tickets remain manageable

#### Phase 3: Block High-Risk Operations
```json
{
  "integrity_enforcement_level": "block_high_risk",
  "integrity_high_risk_operations": "auth_create_account,sync_cloud_data,share_simulation"
}
```

**Behavior:**
- Failed checks block high-risk operations
- Low-risk operations still proceed
- Users shown error message for blocked operations

**High-Risk Operations:**
- `auth_create_account`
- `auth_sign_in`
- `sync_cloud_data`
- `share_simulation`
- `save_custom_scenario`

**Purpose:** Protect critical functionality while minimizing impact on basic usage

**Duration:** 2-4 weeks

**Success Criteria:** Block rate < 0.5%, no increase in false positives

#### Phase 4: Block All Operations
```json
{
  "integrity_enforcement_level": "block_all"
}
```

**Behavior:**
- All failed integrity checks block operations
- Maximum security enforcement

**Purpose:** Full protection against device/app integrity violations

**When to Deploy:** After successful Phase 3, false positive rate < 0.1%

### Firebase Remote Config Setup

#### Remote Config Parameters

In Firebase Console → Remote Config:

**`integrity_enabled`** (Boolean, default: `true`)
- Master switch to enable/disable all Play Integrity checks globally
- When false, all integrity checks are skipped regardless of other settings

**`integrity_enforcement_level`** (String, default: `"log_only"`)
- Controls Play Integrity enforcement behavior
- Valid values: `log_only`, `warn_user`, `block_high_risk`, `block_all`

**`integrity_high_risk_operations`** (String)
- Default: `"auth_create_account,auth_sign_in,sync_cloud_data,share_simulation,save_custom_scenario"`
- Comma-separated list of operations requiring high security

**`integrity_bypass_development`** (Boolean, default: `true`)
- Bypass integrity checks in debug builds

#### Rollout Conditions

**Beta Users:**
- User property: `integrity_beta` = `true`
- Enforcement level: `warn_user`

**Production:**
- 100% of users
- Enforcement level: `log_only` (gradually increase)

#### Rollout Timeline

| Week | Enforcement Level | User % | Rollback Trigger |
|------|------------------|--------|------------------|
| 1-2  | `log_only` | 100% | N/A (monitoring only) |
| 3    | `warn_user` | 1% (beta) | >5% error rate increase |
| 4    | `warn_user` | 10% | >2% support ticket increase |
| 5    | `warn_user` | 100% | >1% user churn increase |
| 6-7  | `block_high_risk` | 1% (beta) | >10% block rate |
| 8    | `block_high_risk` | 10% | >5% block rate |
| 9-10 | `block_high_risk` | 100% | >1% block rate |
| 11+  | `block_all` | Gradual | >0.5% block rate |

## Backend Implementation

### Security Requirements

Three mandatory requirements for production security:

1. **Backend Nonce Generation** - Client-side generation is insecure
2. **Backend Token Verification** - Tokens must be verified with Google's API
3. **Verdict Checking** - Check deviceIntegrity and appIntegrity verdicts

### Step 1: Backend Nonce Generation

`POST /api/integrity/nonce`

```typescript
// Example Node.js/Express implementation
import crypto from 'crypto';
import { redis } from './redis'; // Your Redis client

app.post('/api/integrity/nonce', async (req, res) => {
  const { userId } = req.body;
  
  // Generate cryptographically secure nonce
  const nonce = crypto.randomBytes(32).toString('base64');
  
  // Store nonce in Redis with 5-minute expiration
  await redis.setex(
    `integrity_nonce:${userId}:${nonce}`,
    300, // 5 minutes
    JSON.stringify({
      userId,
      createdAt: Date.now(),
      used: false,
    })
  );
  
  res.json({ nonce });
});
```

**Client Usage:**

```dart
class BackendService {
  Future<String> generateIntegrityNonce(String userId) async {
    final response = await http.post(
      Uri.parse('$baseUrl/api/integrity/nonce'),
      body: jsonEncode({'userId': userId}),
    );
    
    if (response.statusCode != 200) {
      throw Exception('Failed to generate nonce');
    }
    
    return jsonDecode(response.body)['nonce'] as String;
  }
}

Future<void> _verifyDeviceIntegrity(String userId, String operationId) async {
  final nonce = await BackendService().generateIntegrityNonce(userId);
  
  await PlayIntegrityService().verifyWithEnforcement(
    operationId: operationId,
    userId: userId,
    nonce: nonce,
  );
}
```

### Step 2: Backend Token Verification

`POST /api/integrity/verify`

```typescript
import axios from 'axios';

app.post('/api/integrity/verify', async (req, res) => {
  const { token, nonce, userId } = req.body;
  
  // 1. Verify nonce is valid and not used
  const nonceKey = `integrity_nonce:${userId}:${nonce}`;
  const nonceData = await redis.get(nonceKey);
  
  if (!nonceData) {
    return res.status(400).json({ error: 'Invalid or expired nonce' });
  }
  
  const nonce = JSON.parse(nonceData);
  if (nonce.used) {
    return res.status(400).json({ error: 'Nonce already used' });
  }
  
  // 2. Mark nonce as used (prevent replay attacks)
  await redis.setex(nonceKey, 300, JSON.stringify({ ...nonce, used: true }));
  
  // 3. Verify token with Google Play Integrity API
  try {
    const response = await axios.post(
      `https://playintegrity.googleapis.com/v1/io.chipper.graviton:decodeIntegrityToken`,
      { integrity_token: token },
      {
        headers: {
          'Authorization': `Bearer ${YOUR_GOOGLE_API_KEY}`,
          'Content-Type': 'application/json',
        },
      }
    );
    
    const verdict = response.data.tokenPayloadExternal;
    
    // 4. Check verdicts
    const deviceIntegrity = verdict.deviceIntegrity?.deviceRecognitionVerdict || [];
    const appIntegrity = verdict.appIntegrity?.appRecognitionVerdict;
    
    const isDeviceValid = deviceIntegrity.includes('MEETS_DEVICE_INTEGRITY');
    const isAppValid = appIntegrity === 'PLAY_RECOGNIZED' || 
                       appIntegrity === 'UNRECOGNIZED_VERSION';
    
    // 5. Return verdict
    res.json({
      valid: isDeviceValid && isAppValid,
      deviceIntegrity,
      appIntegrity,
      accountDetails: verdict.accountDetails,
    });
    
  } catch (error) {
    console.error('Token verification failed:', error);
    res.status(500).json({ error: 'Verification failed' });
  }
});
```

**Client Usage:**

```dart
class BackendService {
  Future<bool> verifyIntegrityToken({
    required String token,
    required String nonce,
    required String userId,
  }) async {
    final response = await http.post(
      Uri.parse('$baseUrl/api/integrity/verify'),
      body: jsonEncode({
        'token': token,
        'nonce': nonce,
        'userId': userId,
      }),
    );
    
    if (response.statusCode != 200) {
      return false;
    }
    
    final result = jsonDecode(response.body);
    return result['valid'] as bool;
  }
}

Future<void> _verifyDeviceIntegrity(String userId, String operationId) async {
  final nonce = await BackendService().generateIntegrityNonce(userId);
  
  await PlayIntegrityService().verifyWithEnforcement(
    operationId: operationId,
    userId: userId,
    nonce: nonce,
    verifyTokenCallback: (token) async {
      return await BackendService().verifyIntegrityToken(
        token: token,
        nonce: nonce,
        userId: userId,
      );
    },
  );
}
```

### Analytics Queries

```sql
-- Monitor success rate
SELECT 
  param.value.string_value AS operation_id,
  COUNT(*) as total_checks,
  COUNTIF(param2.value.string_value = 'success') as successes,
  SAFE_DIVIDE(COUNTIF(param2.value.string_value = 'success'), COUNT(*)) * 100 as success_rate
FROM `your-project.analytics.events_*`,
UNNEST(event_params) AS param,
UNNEST(event_params) AS param2
WHERE event_name = 'integrity_verification'
  AND param.key = 'operation_id'
  AND param2.key = 'status'
  AND _TABLE_SUFFIX BETWEEN '20240101' AND '20240131'
GROUP BY operation_id
ORDER BY total_checks DESC;

-- Monitor block rate by operation
SELECT 
  param.value.string_value AS operation_id,
  COUNTIF(param2.value.string_value = 'failed' 
    AND param3.value.string_value IN ('block_high_risk', 'block_all')) as blocked_operations,
  COUNT(*) as total_operations,
  SAFE_DIVIDE(blocked_operations, COUNT(*)) * 100 as block_rate_percent
FROM `your-project.analytics.events_*`,
UNNEST(event_params) AS param,
UNNEST(event_params) AS param2,
UNNEST(event_params) AS param3
WHERE event_name = 'integrity_verification'
  AND param.key = 'operation_id'
  AND param2.key = 'status'
  AND param3.key = 'enforcement_level'
GROUP BY operation_id
HAVING block_rate_percent > 0
ORDER BY block_rate_percent DESC;
```

## Rollback Procedures

### Rollback Triggers
- False positive rate > 5%
- API availability < 95%
- Support ticket spike > 200%
- User churn increase > 3%

### Rollback Steps

1. Update Remote Config to `log_only`
2. Monitor for stabilization (5-10 minutes)
3. Communicate to users
4. Investigate and fix root cause
5. Re-rollout from Phase 1

## Security

### Protection Scope

**Protects Against:**
- Fraudulent account creation
- Unauthorized app modifications
- Emulator/rooted device attacks
- Replay attacks (via nonces)
- Bot/automated abuse

**Does Not Protect Against:**
- Man-in-the-middle attacks (use HTTPS)
- Compromised credentials (use MFA)
- Social engineering
- Physical device theft

### Best Practices

1. Always verify tokens server-side
2. Use short-lived backend-generated nonces
3. Monitor failure rates for attack indicators
4. Implement defense in depth
5. Handle failures gracefully
6. Sanitize error messages to clients
7. Log comprehensive details server-side
