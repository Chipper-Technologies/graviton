# Play Integrity API Integration

## ⚠️ CRITICAL SECURITY REQUIREMENT

**Backend token verification is MANDATORY for production use.** Without it, this integration provides **zero security value** while adding latency to operations.

The current implementation:
- ✅ Generates integrity tokens on the client
- ✅ Implements phased enforcement rollout
- ❌ **DOES NOT verify tokens with Google's backend API by default**
- ⚠️ Requires you to implement and provide `verifyTokenCallback` for actual security

**Without backend verification, tokens could be:**
- Generated by compromised/rooted devices
- Created by tampered/repackaged apps
- Replayed or forged by attackers

See the [Backend Implementation Required](#backend-implementation-required) section below for implementation details.

## Overview

The Google Play Integrity API has been fully integrated into Graviton to protect against fraud, cheating, and unauthorized access. This integration helps ensure that app interactions are coming from legitimate, unmodified builds running on genuine Android devices.

## What is Play Integrity API?

Play Integrity API helps you check that interactions with your app are from:
- **Legitimate installs** from Google Play
- **Genuine Android devices** (not emulators or rooted devices)
- **Unmodified app binaries** (not tampered or repackaged)

**Note:** These checks only work when you verify tokens with Google's backend API.

## Production Deployment

## Backend Implementation Required

### ⚠️ CRITICAL SECURITY REQUIREMENTS

The Play Integrity implementation has **THREE MANDATORY REQUIREMENTS** for production security:

1. **Backend Nonce Generation** - Client-side nonce generation is INSECURE
2. **Backend Token Verification** - Tokens MUST be verified with Google's API
3. **Verdict Checking** - You must check deviceIntegrity and appIntegrity verdicts

**Without all three, the Play Integrity integration provides ZERO security value.**

Current state:
- ❌ Client-side nonce fallback (insecure, logs warnings)
- ❌ No token verification with Google (tokens generated but never checked)
- ❌ No verdict validation (can't distinguish legitimate from compromised devices)

### Backend Implementation (REQUIRED FOR PRODUCTION)

#### Step 1: Backend Nonce Generation

**Why Required**: Client-side nonces can be tampered with, allowing attackers to replay old tokens or bypass verification entirely.

**Backend Endpoint**: `POST /api/integrity/nonce`

```typescript
// Example Node.js/Express implementation
import crypto from 'crypto';
import { redis } from './redis'; // Your Redis client

app.post('/api/integrity/nonce', async (req, res) => {
  const { userId } = req.body;
  
  // Generate cryptographically secure nonce
  const nonce = crypto.randomBytes(32).toString('base64');
  
  // Store nonce in Redis with 5-minute expiration
  await redis.setex(
    `integrity_nonce:${userId}:${nonce}`,
    300, // 5 minutes
    JSON.stringify({
      userId,
      createdAt: Date.now(),
      used: false,
    })
  );
  
  res.json({ nonce });
});
```

**Client Usage**:

```dart
// lib/services/backend_service.dart
class BackendService {
  Future<String> generateIntegrityNonce(String userId) async {
    final response = await http.post(
      Uri.parse('$baseUrl/api/integrity/nonce'),
      body: jsonEncode({'userId': userId}),
    );
    
    if (response.statusCode != 200) {
      throw Exception('Failed to generate nonce');
    }
    
    return jsonDecode(response.body)['nonce'] as String;
  }
}

// lib/services/auth_service.dart
Future<void> _verifyDeviceIntegrity(String userId, String operationId) async {
  try {
    // ✅ Fetch nonce from backend (secure)

    // Request token with backend nonce
    await PlayIntegrityService().verifyWithEnforcement(
      operationId: operationId,
      userId: userId,
      nonce: nonce, // Backend-generated
    );
  } catch (e) {
    // Handle errors
  }
}
```

#### Step 2: Backend Token Verification (MANDATORY)

⚠️ **THIS IS THE MOST CRITICAL STEP** - Without this, Play Integrity provides ZERO security.

The client-side `verifyWithEnforcement()` method accepts a `verifyTokenCallback` parameter that **MUST** be provided for production security. This callback should call your backend to verify the token with Google's Play Integrity API.

**Backend Endpoint**: `POST /api/integrity/verify`

```typescript
import axios from 'axios';

app.post('/api/integrity/verify', async (req, res) => {
  const { token, nonce, userId } = req.body;
  
  // 1. Verify nonce is valid and not used
  const nonceKey = `integrity_nonce:${userId}:${nonce}`;
  const nonceData = await redis.get(nonceKey);
  
  if (!nonceData) {
    return res.status(400).json({ error: 'Invalid or expired nonce' });
  }
  
  const nonce = JSON.parse(nonceData);
  if (nonce.used) {
    return res.status(400).json({ error: 'Nonce already used' });
  }
  
  // 2. Mark nonce as used (prevent replay attacks)
  await redis.setex(nonceKey, 300, JSON.stringify({ ...nonce, used: true }));
  
  // 3. Verify token with Google Play Integrity API
  try {
    const response = await axios.post(
      `https://playintegrity.googleapis.com/v1/io.chipper.graviton:decodeIntegrityToken`,
      { integrity_token: token },
      {
        headers: {
          'Authorization': `Bearer ${YOUR_GOOGLE_API_KEY}`,
          'Content-Type': 'application/json',
        },
      }
    );
    
    const verdict = response.data.tokenPayloadExternal;
    
    // 4. Check verdicts
    const deviceIntegrity = verdict.deviceIntegrity?.deviceRecognitionVerdict || [];
    const appIntegrity = verdict.appIntegrity?.appRecognitionVerdict;
    
    const isDeviceValid = deviceIntegrity.includes('MEETS_DEVICE_INTEGRITY');
    const isAppValid = appIntegrity === 'PLAY_RECOGNIZED' || 
                       appIntegrity === 'UNRECOGNIZED_VERSION';
    
    // 5. Return verdict
    res.json({
      valid: isDeviceValid && isAppValid,
      deviceIntegrity,
      appIntegrity,
      accountDetails: verdict.accountDetails,
    });
    
  } catch (error) {
    console.error('Token verification failed:', error);
    res.status(500).json({ error: 'Verification failed' });
  }
});
```

**Client Usage (REQUIRED)**:

```dart
// 1. Create backend service method for token verification
class BackendService {
  Future<bool> verifyIntegrityToken({
    required String token,
    required String nonce,
    required String userId,
  }) async {
    final response = await http.post(
      Uri.parse('$baseUrl/api/integrity/verify'),
      body: jsonEncode({
        'token': token,
        'nonce': nonce,
        'userId': userId,
      }),
    );
    
    if (response.statusCode != 200) {
      return false;
    }
    
    final result = jsonDecode(response.body);
    return result['valid'] as bool;
  }
}

// 2. Use verifyTokenCallback in ALL integrity verification calls
// lib/services/auth_service.dart
Future<void> _verifyDeviceIntegrity(String userId, String operationId) async {
  try {
    // Fetch nonce from backend
    final nonce = await BackendService().generateIntegrityNonce(userId);
    
    // ✅ SECURE: Verify with backend callback
    await PlayIntegrityService().verifyWithEnforcement(
      operationId: operationId,
      userId: userId,
      nonce: nonce,
      verifyTokenCallback: (token) async {
        // This callback MUST be provided for production security
        return await BackendService().verifyIntegrityToken(
          token: token,
          nonce: nonce,
          userId: userId,
        );
      },
    );
  } catch (e) {
    // Handle verification failures
    rethrow;
  }
}

// ❌ INSECURE: Without verifyTokenCallback (development/monitoring only)
await PlayIntegrityService().verifyWithEnforcement(
  operationId: operationId,
  userId: userId,
  // NO verifyTokenCallback = tokens generated but NEVER verified
  // Logs security warnings in production
);
```

## Security Considerations

### What This Protects Against
- ✅ Fraudulent account creation
- ✅ Unauthorized app modifications
- ✅ Emulator/rooted device attacks
- ✅ Replay attacks (via nonces)
- ✅ Bot/automated abuse

### What This Doesn't Protect Against
- ❌ Man-in-the-middle attacks (use HTTPS)
- ❌ Compromised user credentials (use MFA)
- ❌ Social engineering
- ❌ Physical device theft
- ❌ Advanced persistent threats

### Best Practices

1. **Always verify tokens server-side** - Never trust client results
2. **Use short-lived nonces** - Generate on backend, expire quickly
3. **Monitor failure rates** - Sudden spikes may indicate attacks
4. **Combine with other security** - Defense in depth approach
5. **Handle failures gracefully** - Don't lock out legitimate users
